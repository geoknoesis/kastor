**Prioritized findings.** P0 means immediate data-safety blocker; P1 means fix before stable release; P2 means material improvement or a limitation requiring explicit scope. “Reproduced” means an executable probe confirmed the behavior. “Static” means the implementation supports the finding but a dedicated regression test was not run.

1. **P0 — Opening a TDB2 inference repository deletes existing default-graph data. Reproduced.** [JenaRepository.kt:54](../../../rdf/providers/jena/src/main/kotlin/com/geoknoesis/kastor/rdf/jena/JenaRepository.kt#L54) creates an inference view over the existing default model, clears that same backing model, then adds from the view. A probe wrote and closed a TDB2 store, reopened it through `Tdb2RepositoryWithInference`, and the original triple was gone. The memory inference factory likewise fails to infer `a rdf:type D` after adding `C subClassOf D` and `a rdf:type C`. Replace the destructive copy with a correctly managed inference view/query layer. Add close/reopen preservation and post-construction entailment tests for both factories.

2. **P1 — Jena dataset import violates the additive import contract and loses data. Reproduced.** [JenaProvider.kt:194](../../../rdf/providers/jena/src/main/kotlin/com/geoknoesis/kastor/rdf/jena/JenaProvider.kt#L194), also `copyDataset` at line 155, clears the destination default graph and replaces incoming named graphs. The core contract says parsed data is added, and the non-Jena branch adds rather than replaces. Importing a different triple removed the previously stored triple in the probe. Make append/replace an explicit option, default consistently to the documented behavior, and transact the entire import.

3. **P1 — Core graph isomorphism produces false positives. Reproduced.** [GraphIsomorphism.kt:123](../../../rdf/core/src/main/kotlin/com/geoknoesis/kastor/rdf/GraphIsomorphism.kt#L123) reduces every IRI, including predicates, to `IRI`, and literals to datatype/language categories. `<urn:a> <urn:p> "Alice"` and `<urn:b> <urn:q> "Bob"` returned isomorphic. It also treats matching refinement-label multisets as a complete proof without verifying a node mapping. Preserve fixed RDF term identity and use exact blank-node mapping verification. The separate `rdf-testkit` comparator delegates to Jena and is not the defective implementation; consolidate the semantics without forcing Jena into core.

4. **P1 — Isomorphism refinement can consume explosive amounts of memory. Static complexity finding.** [GraphIsomorphism.kt:211](../../../rdf/core/src/main/kotlin/com/geoknoesis/kastor/rdf/GraphIsomorphism.kt#L211) constructs each new label from the entire old label and all neighboring labels. Labels keep growing, so literal string equality does not detect a stable partition; the loop can run `V` rounds. On branching cyclic graphs, label size can grow exponentially with rounds. Initial in-degree calculation also repeatedly scans the graph. Intern signatures to compact color IDs, compare partitions for convergence, and precompute incoming adjacency. Benchmark cyclic and symmetric graphs before retaining this implementation.

5. **P2 — Blank-node mapping is a public stub. Static.** [GraphIsomorphism.kt:259](../../../rdf/core/src/main/kotlin/com/geoknoesis/kastor/rdf/GraphIsomorphism.kt#L259) returns an empty map for every graph pair accepted by the checker, even when a nonempty blank-node correspondence is needed. Implement and verify the mapping or explicitly report unsupported behavior. An empty success value is misleading.

6. **P1 — Default-graph SPARQL mutations render invalid syntax. Reproduced syntax failure.** [SparqlRepository.kt:228](../../../rdf/sparql/endpoint/src/main/kotlin/com/geoknoesis/kastor/rdf/sparql/SparqlRepository.kt#L228) always emits an inner `{ ... }`, even when the `GRAPH` clause is empty. This yields `INSERT DATA { { ... } }`, which the Jena update parser rejected. The same pattern occurs in batch insert, delete, and the default delete template used by graph clearing. Render default triples directly inside the update template; wrap only named graph data. Parse every generated query/update in tests, then execute against a local endpoint.

7. **P1 — Filtered remote graph reads reconstruct unbound variables. Static.** [SparqlRepository.kt:323](../../../rdf/sparql/endpoint/src/main/kotlin/com/geoknoesis/kastor/rdf/sparql/SparqlRepository.kt#L323) substitutes a supplied subject/predicate/object into the pattern, still selects `?s ?p ?o`, then casts every binding as non-null. A supplied subject means `?s` is not bound by the generated pattern; a matching result can fail during reconstruction. Use the supplied constants when constructing the result, or explicitly bind them. Test all eight combinations of bound/unbound positions.

8. **P1 — Remote blank-node operations do not preserve graph semantics. Static, specification-supported.** The same SPARQL graph implementation renders blank-node labels in `DELETE DATA`, where they are prohibited. Separate `INSERT DATA` requests also cannot use a repeated label to establish cross-request identity. This makes per-triple insertion of a connected blank-node structure unsafe. Use a single bounded insert for each blank-node-connected component, a documented skolemization strategy, and pattern-based deletion or explicit rejection when identity cannot be preserved. [W3C SPARQL Update](https://www.w3.org/TR/sparql11-update/) defines these restrictions.

9. **P2 — HTTP results silently discard unsupported terms and malformed result envelopes. Static.** [SparqlRepository.kt:466](../../../rdf/sparql/endpoint/src/main/kotlin/com/geoknoesis/kastor/rdf/sparql/SparqlRepository.kt#L466) returns an empty list when `results.bindings` is missing, and drops unrecognized binding types through `mapNotNull`. The formatter also omits language direction and emits the older triple syntax, while repository capabilities unconditionally claim RDF-star support. Distinguish an empty successful result from an unsupported/malformed response. Negotiate or configure endpoint capabilities; reject unsupported RDF terms instead of losing information.

10. **P1 — Resource SHACL validation discards context required by paths and nested shapes. Reproduced.** [NativeShaclValidator.kt:235](../../../rdf/shacl/validation/src/main/kotlin/com/geoknoesis/kastor/rdf/shacl/providers/NativeShaclValidator.kt#L235) keeps only triples touching the requested resource, then runs whole-graph validation on that fragment. For `a p b; b q "ok"` and a minimum-count path `(p q)` on `a`, full validation passed while `validateResource(a)` failed. Preserve the full data graph and restrict the focus-node plan, rather than deleting supporting data. Also prevent unrelated target nodes from being introduced by the fragment.

11. **P1 — A violation cap can turn an invalid graph into a valid result. Reproduced.** [NativeShaclValidator.kt:124](../../../rdf/shacl/validation/src/main/kotlin/com/geoknoesis/kastor/rdf/shacl/providers/NativeShaclValidator.kt#L124) stops after the cap and calculates `isValid` only from the retained results. With a warning first, an actual violation second, and `maxViolations = 1`, the probe changed from invalid to valid. `violationsTruncated = true` does not make `conforms()` safe because it reads `isValid`. Separate diagnostic storage limits from conformance computation, or return an explicit indeterminate outcome. Test mixed severities and ordering.

12. **P1 — SHACL SPARQL pre-binding is textual substitution, not variable binding. Static.** [SparqlConstraintEvaluator.kt:32](../../../rdf/shacl/validation/src/main/kotlin/com/geoknoesis/kastor/rdf/shacl/native/SparqlConstraintEvaluator.kt#L32) replaces `$this` throughout text after the first `{`, including strings/comments and positions that require a variable, such as `BOUND($this)`. Blank-node focus values are left unbound. Use provider initial bindings or an AST-aware mechanism, preserving the same focus-node semantics for IRIs and blank nodes. Add literal/comment, `BOUND`, subquery, and blank-node tests.

13. **P1 — Native validation exposes controls it does not enforce. Static.** [ValidationConfig.kt:8](../../../rdf/shacl/validation/src/main/kotlin/com/geoknoesis/kastor/rdf/shacl/ValidationConfig.kt#L8) exposes timeout, parallel, and streaming controls, but the native execution path does not consume those controls. The native provider advertises parallel validation despite a sequential loop. Regex evaluation has no effective deadline; the graph-size check runs before imported/discovered shapes are expanded, leaving those additions outside the estimate. Implement deadline/cancellation checks and post-expansion limits; reject unsupported modes. For untrusted shapes, address pathological regex execution separately because an outer elapsed-time check cannot interrupt a blocking match.

14. **P2 — Compiled shape cache has unbounded process lifetime and global version tags. Static.** [NativeCompileCache.kt:6](../../../rdf/shacl/validation/src/main/kotlin/com/geoknoesis/kastor/rdf/shacl/native/NativeCompileCache.kt#L6) keeps every compiled shape graph and every tag/digest pair forever. Repeated unique tenant shapes cause retained-heap growth; unrelated callers reusing a tag like `v1` can conflict. Add a bounded cache, size/eviction metrics, explicit invalidation, and caller/validator-scoped tag namespaces. Avoid duplicate compilation under contention.

15. **P1 for scale — Individual domain-property access repeatedly reads the entire graph. Static.** [KastorGraphOps.kt:34](../../../kastor-gen/runtime/src/main/kotlin/com/geoknoesis/kastor/gen/runtime/KastorGraphOps.kt#L34), `PropertyBagImpl`, `ResourceViews`, and write helpers call `getTriples()` before filtering by subject/predicate. Reading `P` properties on `M` objects from `N` triples can cost approximately `O(M × P × N)` scans/conversions before per-wrapper caching helps. On the HTTP provider, this can repeatedly transfer the entire remote graph. Add a graph pattern API with backend pushdown and memory indexes. Batch materialization by subject; measure triples read and bytes transferred, not just wall-clock time.

16. **P2 — Query sequences and flows usually buffer the complete result first. Static.** [JenaRepository.kt:125](../../../rdf/providers/jena/src/main/kotlin/com/geoknoesis/kastor/rdf/jena/JenaRepository.kt#L125) and `Rdf4jRepository.select` collect all bindings before returning. CONSTRUCT/DESCRIBE similarly build lists. HTTP SELECT builds a full response string, JSON tree, and binding list; even error bodies are fully read before truncation. A downstream `take(1)` or Flow buffer cannot reduce upstream work. Introduce scoped closeable cursors/flows with cancellation, configurable response limits, and explicit ownership. Keep eager convenience methods separately documented.

17. **P1 for long-running services — Streaming parse loses the parser's close/cancel handle. Static resource-lifecycle finding.** [JenaProvider.kt:118](../../../rdf/providers/jena/src/main/kotlin/com/geoknoesis/kastor/rdf/jena/JenaProvider.kt#L118) wraps the asynchronous parser iterator in a plain Sequence. Early termination, downstream exceptions, or Flow cancellation cannot explicitly close that iterator; the producer may remain waiting on its bounded queue. The comment asks callers to consume everything, while tests encourage `take(1)`. Expose a scoped stream or closeable iterator and ensure cancellation closes both parser and conversion resources. Verify thread termination with an input larger than the queue.

18. **P1 — Memory transactions claim support without rollback or isolation. Reproduced.** [MemoryRepositoryProvider.kt:139](../../../rdf/core/src/main/kotlin/com/geoknoesis/kastor/rdf/provider/MemoryRepositoryProvider.kt#L139) invokes the block directly, while capabilities report transaction support. A write followed by an exception retained the triple. Either implement transactions or report unsupported capability and reject the operation explicitly. Separately, writes after `close()` succeeded in the probe; add repository/graph lifecycle guards or clearly define detached graph behavior.

19. **P2 — Provider contracts are inconsistent beyond transactions. Static.** `MemoryRepository.createGraph` rejects duplicates, while Jena/RDF4J return a graph; empty graph presence differs; remote `clear()` clears only the default graph while memory/RDF4J clear the repository. Jena and RDF4J repository capability objects claim inference regardless of the concrete variant, and the Jena repository capabilities omit richer values supplied by its provider. Jena nesting always starts a transaction while RDF4J joins the outer one. Define the contract for graph presence, clearing, nested transactions, return booleans, and close behavior, and test the same matrix across providers. Do not silently fake backend features.

20. **P1 — Ontology generation does not track input file contents. Static, Gradle contract confirmed.** [OntologyGenerationTask.kt:32](../../../kastor-gen/gradle-plugin/src/main/kotlin/com/geoknoesis/kastor/gen/gradle/tasks/OntologyGenerationTask.kt#L32) declares SHACL/context paths as `@Input Property<String>` on a cacheable task. Editing a file at the same path does not change that input fingerprint, so generated code can remain stale. Resolve inputs to `RegularFileProperty` annotated `@InputFile` with appropriate path sensitivity. Add a TestKit test that changes content without renaming the file and verifies regeneration. [Gradle InputFile documentation](https://docs.gradle.org/current/javadoc/org/gradle/api/tasks/InputFile.html) explicitly distinguishes content tracking from a string path input.

21. **P1 — Separate packages and JSON-LD renamed types are not consistently generated. Static.** [OntologyGenerationTask.kt:254](../../../kastor-gen/gradle-plugin/src/main/kotlin/com/geoknoesis/kastor/gen/gradle/tasks/OntologyGenerationTask.kt#L254) passes the wrapper package to a generator that uses that same package for its domain superinterface at [OntologyWrapperGenerator.kt:84](../../../kastor-gen/processor/src/main/kotlin/com/geoknoesis/kastor/gen/processor/internal/codegen/OntologyWrapperGenerator.kt#L84). When interface and wrapper packages differ, the reference points at the wrong type. The task also looks up outputs using context-renamed names, but the generators key them by names extracted from target-class IRIs; nullable lookups silently omit files. Pass one resolved type-name/package model through all generators and compile the advertised sample configurations as consumer tests.

22. **P2 — Generator outputs and KSP rounds need stronger incremental handling. Static.** The generation task writes current files without removing obsolete generated files, so deleted/renamed shapes or disabled output modes can leave stale Kotlin in the output directory. In [OntoMapperProcessor.kt:26](../../../kastor-gen/processor/src/main/kotlin/com/geoknoesis/kastor/gen/processor/internal/core/OntoMapperProcessor.kt#L26), symbols are analyzed/generated before invalid symbols are deferred, and `processedClasses` is populated during analysis; a later valid round can then be skipped. Reconcile only files owned by the generator, validate before analyzing, and mark classes processed only after successful generation. Test shape removal and references produced by another KSP processor.

23. **P2 — Materialization registration is a shared mutable unsynchronized map. Static.** [Materialization.kt:92](../../../kastor-gen/runtime/src/main/kotlin/com/geoknoesis/kastor/gen/runtime/Materialization.kt#L92) exposes a mutable global registry. Parallel class initialization can register different wrappers while other threads read the map. Per-class initialization locks do not protect a shared map across classes. Use a concurrent registry with an explicit duplicate-registration policy; consider class-loader lifetime in servers. Also state clearly that memoized delegates/extras are snapshots: graph changes after first access are not reflected. Snapshot behavior may be intentional, but should not be described as an automatically live view.

24. **P1 — HermiT classification returns placeholder results. Static.** [HermitRdfReasoner.kt:124](../../../rdf/reasoning/hermit/src/main/kotlin/com/geoknoesis/kastor/rdf/hermit/HermitRdfReasoner.kt#L124) uses `emptyClassification()` even for nonempty ontologies, and `classify()` returns that empty result. Class/property counters also remain zero. Implement hierarchy and instance extraction from the reasoner or explicitly report classification unsupported. Test a simple subclass hierarchy and assert nonempty classifications.

25. **P2 — HermiT work has incomplete lifecycle and effective limits. Static.** [HermitRdfReasoner.kt:54](../../../rdf/reasoning/hermit/src/main/kotlin/com/geoknoesis/kastor/rdf/hermit/HermitRdfReasoner.kt#L54) creates a reasoner without a `finally` that disposes it, including the inconsistent-ontology return path. Configured timeout/memory/streaming settings are not enforced in this adapter. The materialization threshold is checked only after inferred data has been fully generated, serialized, parsed, and collected. `isConsistent()` also calls the full materialization path. Separate consistency, classification, and materialization, configure supported limits at the engine boundary, dispose on every exit, and bound output during production.

26. **P2 — Model download/cache behavior is fragile on a fresh machine. Static.** [ModelDownloader.kt:41](../../../tools/onto-quality/embed/src/main/kotlin/com/geoknoesis/kastor/ontoquality/embed/ModelDownloader.kt#L41) leaves Java HTTP redirects disabled, so a redirecting model URL fails rather than downloading. The client default is `NEVER`, per [Oracle HttpClient documentation](https://docs.oracle.com/en/java/javase/24/docs/api/java.net.http/java/net/http/HttpClient.html). A live download was not attempted. URLs use mutable `main` revisions with fixed hashes, producing availability failures if upstream content changes. Full byte-array download/hash and direct writes also cause avoidable memory use and interrupted/concurrent-cache races. Pin an immutable revision, permit a controlled redirect policy, stream/hash to a temporary file, and atomically publish under a cache lock. Existing hash verification is a good safeguard and should remain.

27. **P2 — ONNX cleanup does not cover all owned native resources. Static.** [OnnxEmbeddingModel.kt:40](../../../tools/onto-quality/embed/src/main/kotlin/com/geoknoesis/kastor/ontoquality/embed/OnnxEmbeddingModel.kt#L40) creates session options without closing them, and `close()` only closes the session, not the tokenizer. A tokenizer-construction failure can leave an already-created session unclosed, and close is not coordinated with the inference lock. Own/dispose each native resource explicitly and test repeated create/use/close plus concurrent close. Tensor/result cleanup inside inference is already substantially better.

28. **P2 — Similarity search and deep graph traversal have predictable scaling limits. Static.** [SimilarityIndex.kt:20](../../../tools/onto-quality/embed/src/main/kotlin/com/geoknoesis/kastor/ontoquality/embed/SimilarityIndex.kt#L20) compares every pair across embedding dimensions: `O(n²d)`. At 10,000 resources it performs 49,995,000 pair comparisons before dimension work. Keep an exact bounded mode, then add blocking/candidate pruning or an approximate index with measured recall. Validate vector dimension/normalization. `CycleDetector.strongConnect` also uses recursion proportional to path depth, risking stack overflow on deep taxonomies; use an iterative traversal or an explicit supported-depth limit.

29. **P2 — Native SHACL does avoidable graph copying and repeated setup. Static.** [NativeShaclValidator.kt:118](../../../rdf/shacl/validation/src/main/kotlin/com/geoknoesis/kastor/rdf/shacl/providers/NativeShaclValidator.kt#L118) constructs a shapes graph, merges all data and shapes even for Core-only validation, builds further indexes, and rereads triples for statistics. SPARQL constraints construct a new Dataset per evaluation, potentially materializing a provider repository repeatedly. Compile regexes once per compiled constraint; build merged/query views only if needed; reuse indexes and one scoped query dataset per validation run. Benchmark preparation separately from constraint execution and report peak retained heap.

30. **P1 — Release-critical behavior is not protected by the current test gates. Static plus fresh test evidence.** [JenaVariantsTest.kt:10](../../../rdf/providers/jena/src/test/kotlin/com/geoknoesis/kastor/rdf/jena/JenaVariantsTest.kt#L10) and [Rdf4jVariantsTest.kt:34](../../../rdf/providers/rdf4j/src/test/kotlin/com/geoknoesis/kastor/rdf/rdf4j/Rdf4jVariantsTest.kt#L34) disable persistence tests. Their existing forms also need proper transaction/close/reopen handling. The HTTP provider has only one reported test; the Gradle plugin test task has no sources. [conformance.yml:22](../../../.github/workflows/conformance.yml#L22) does not initialize the RDF corpus submodule; the harness skips when it is missing. Require a nonzero expected test count, initialize pinned fixtures, and add persistent-store, generator-consumer, endpoint, and cancellation regressions. Scheduled upstream testing is useful, but it does not substitute for a release gate.

31. **P2 — Build and publication verification are incomplete. Static.** [build.gradle.kts:122](../../../build.gradle.kts#L122) defines a root build that collects assembled artifacts without itself depending on checks. CI explicitly runs tests, which mitigates this there, but the root build contract is misleading. Publications lack a consistently configured remote release/signing/POM-metadata workflow; Kotlin documentation jars may be empty. There is no configured binary API compatibility gate or coverage reporting in the inspected build, and dependency lock/verification files were not found. Add a convention plugin for publication metadata, Kotlin API docs, explicit API/API compatibility checks, and a separate clean consumer build against locally staged artifacts. If Maven Central is the target, complete and validate that publication path before announcing availability. Do not assume a successful local `publishToMavenLocal` verifies public consumption.

32. **P2 — Documentation and configuration imply stronger guarantees than the implementation. Static.** [README.md:150](../../../README.md#L150) markets ACID transactions across all backends and production/streaming readiness despite the above exceptions. The RDF4J “existing repository” example declares a repository but never passes it to Kastor. Provider version metadata is also hardcoded independently of actual dependency versions. Publish a tested capability table and distinguish experimental, eager, snapshot, unsupported, and engine-dependent behavior. Verify documentation examples by compiling/running them. Large files such as `RdfCore.kt` and `NativeShaclValidator.kt`, duplicated provider conversions/query setup, and repeated KSP logger adapters would benefit from focused extraction after correctness fixes.

33. **P2 — Default asynchronous URL loading has no concurrency bound. Static.** [RdfCore.kt:81](../../../rdf/core/src/main/kotlin/com/geoknoesis/kastor/rdf/RdfCore.kt#L81) uses a cached thread pool for blocking URL work. A burst of slow requests can create many threads even though each connection has timeouts. Supply a bounded executor/admission policy or explicit caller-owned concurrency, and propagate cancellation to the underlying I/O. Measure simultaneous requests, queue delay, thread count, and rejected work under load.

**Performance work should prioritize algorithmic changes.** None of the following is a measured production throughput claim; these are costs visible in the implementation and proposed measurements.

| Priority | Path | Present cost/risk | Improvement | Meaningful benchmark |
|---|---|---|---|---|
| 1 | Isomorphism | Expanding nested labels, repeated graph scans | Compact color refinement plus exact verification | Cycles, symmetric graphs, fixed-label differences; peak heap |
| 2 | Domain projection | Approximately `M × P × N` triple inspections | Pattern lookup, subject batching, provider indexes | 1k/10k/100k subjects; backend reads and allocations per object |
| 3 | Query/HTTP results | Full result before first consumer item | Scoped streaming and bounded response parsing | Time to first row, `take(1)`, cancellation, 1M-row heap |
| 4 | Native SHACL | Repeated snapshots/merges/indexes and query setup | Reuse per-run state; lazy SPARQL view | Separate compile, plan, execute, statistics timings |
| 5 | Shape cache | Retention grows with unique shapes/tags | Bounded cache and scoped tags | Many unique tenant schemas; steady-state retained heap |
| 6 | Semantic similarity | `n(n−1)/2 × d` arithmetic | Candidate reduction/ANN when appropriate | 1k/10k/100k labels; recall versus exact results |
| 7 | HermiT | Several full representations; consistency triggers inference export | Separate operations, stream/bound inference, dispose | Repeated consistency-only and materialization runs |
| 8 | URL/parse work | Unbounded concurrency and incomplete early-stop cleanup | Bounded admission and explicit cancellation | Slow server, partial read, exception, thread/resource counts |

Use JMH with warmup/forks and allocation profiling for JVM paths; use deterministic local HTTP fixtures for transport paths. Existing SHACL benchmark infrastructure is a strength. Add thresholds only after stable baselines exist on controlled hardware. Optimizing Kotlin collection syntax alone will not resolve whole-graph transfers or quadratic algorithms.

**Security and operational assessment.** The concrete security-relevant concerns found are denial-of-service/resource exhaustion through ineffective validation limits, expanding labels, unbounded caches/responses, and URL concurrency. This review does not establish a remote exploit in a deployed Kastor service. There is no evidence here of an authentication bypass or a dependency CVE. No dedicated secret-history scan, dependency advisory audit, native-library audit, or adversarial network sandbox test was performed, so this is not a security certification. Positive safeguards include IRI delimiter rejection, SPARQL literal escaping, finite HTTP connect/read timeouts, model hashes, and several scoped RDF4J/Jena resources.

**Recommended release sequence.**

1. Fix findings 1–3, 6–8, 10–13, 18, and 20–21 first. Land a regression test with each change. Disable the inference factories until data preservation is verified if the correct implementation cannot land immediately.
2. Restore trustworthy contracts: exact graph equality/mapping, explicit transaction semantics, truthful capabilities, HermiT classification behavior, and an indeterminate validation outcome when work is truncated.
3. Make fresh persistence reopen tests, generator consumer builds, local endpoint integration, and pinned conformance fixtures mandatory for release. Run a clean build on Linux and Windows with JDK 21; add a test-results count check so skipped corpora cannot look like conformance success.
4. Resolve cancellation and resource ownership before adding streaming APIs. Address whole-graph property reads, cache bounds, and isomorphism complexity before publishing scale claims.
5. Stage and consume the actual published artifacts in an independent project, verify API compatibility/docs, and publish the tested capability matrix. Keep unsupported/experimental paths clearly labeled.

**What is already good.** The provider/domain separation, lightweight SPARQL contract module, sealed RDF term model, KotlinPoet usage, BOM, service-provider organization, substantial unit suites, graph testkit, conformance harness, benchmark infrastructure, contribution/security policies, and extensive documentation are useful foundations. The RDF4J per-operation connection handling and scoped result materialization show attention to resource correctness. The release blockers are specific and fixable; they require targeted corrections and stronger regression gates rather than a wholesale rewrite.
